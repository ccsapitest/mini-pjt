## 발견된 근본 원인 5가지

### A. 요청자 본인 식별 안 됨 (4, 5, 13에 영향)
시스템 프롬프트에 "요청자 본인 조회"라고만 적혀 있고, 실제 이름(`REQUESTER_NAME = "김삼성"`)은
Python 상수로만 존재한다. 사용자가 메시지에 자기 이름을 안 밝히면 모델이 알 방법이 없어 되묻는다.
CLAUDE.md의 "세션 기준 고정 식별" 취지와 어긋난다 — 세션이 고정해주는 게 아니라 매번 사용자가
스스로 이름을 대야 하는 상태다.

### B. `ValidationException: Expected toolResult blocks` (2, 14에 영향)
특정 질문에서 재현되는 실제 버그. Bedrock Converse API가 tool_use 블록에 대응하는 toolResult를
못 찾아서 나는 에러로, 커스텀 미들웨어(`CompanionAuthorizationMiddleware` 등)가 도구 호출을
가로챌 때 메시지 쌍이 깨지는 것으로 추정된다. 원인 특정은 2차 개선 때 디버깅이 필요하다.

### C. 표준 메뉴 데이터 공백 (6에 영향)
"회덮밥", "뼈매운탕", "물냉면" 등 최근 추가한 식당(묵호횟집, 하면옥)의 메뉴가 아직
`menus.json`에 canonical로 없다. 이전에 한 번 언급했던 보충 작업이 안 끝난 상태다.

### D. 저신뢰 매칭 정책이 재시도로 무력화됨 (8에 영향)
"에비덴 왕새우 커리"는 단발 검색으로는 임계값(0.30) 미만이라 "정보 없음"이 나와야 하는데,
실제 실행에서는 모델이 `normalize_menu_names`를 표현을 바꿔가며 4~5번 재호출하다가 결국
"카레"로 매칭시켜 확신에 찬 수치를 제시했다. **"애매하면 보수적으로 제외"라는 설계 의도가
모델의 재시도 행동 앞에서 뚫린 것** — 이번 평가에서 가장 중요한 발견이다.

### E. HITL이 실제로 발동하지 않음 (11, 16, 17에 영향)
`update_user_preference`에 `HumanInTheLoopMiddleware`로 인터럽트를 걸어뒀는데, 모델이 도구를
아예 호출하지 않고 채팅으로 "진행할까요?"라고 먼저 물어버린다. 그래프가 실제로 멈추는 게
아니라 모델이 스스로 예의를 차리는 것뿐이라, 시스템이 승인을 강제한다는 설계 의도가
실현되지 않고 있다. 시스템 프롬프트의 "승인 절차는 시스템이 강제한다"는 문구를 모델이
"내가 먼저 물어봐야 한다"로 오해한 것으로 보인다.

### F. 응답 속도 저하 (전체 영향, 특히 1·3·9번처럼 도구 호출이 많은 케이스)
17개 질의 동안 `Starting MCP server` 로그가 **36번** 찍혔다 — MCP로 연결된 도구
(`get_user_preference`, `get_weather`, `list_restaurants` 등)를 부를 때마다 서버 프로세스를
새로 띄우는 것으로 보이며, 세션을 재사용하지 않는다. 여기에 더해 1번 질의는 도구를 **18번**
호출했는데, ReAct 구조상 도구 호출 1회당 LLM 왕복이 1회 필요해 지연이 그대로 누적된다.
LLM 자체가 느린 게 아니라, **MCP 세션 미재사용 + 도구 호출 횟수가 많은 구조**가 체감 속도
저하의 주 원인이다.

## 2차 개선 우선순위 (제안)
1. **E (HITL)** — 시스템 프롬프트를 "수정 요청은 망설이지 말고 바로 update_user_preference를
   호출하라. 승인 대기는 시스템이 자동으로 처리한다"로 명확히 재작성. 가장 심각한 문제(안전장치
   자체가 검증 불가능한 상태)라 최우선.
2. **A (본인 식별)** — 시스템 프롬프트에 요청자 이름을 직접 주입 (예: `f"요청자 본인의 이름은 {REQUESTER_NAME}이다."`).
3. **B (ValidationException)** — 재현 조건을 좁혀서 미들웨어 반환값 형식 디버깅.
4. **D (재시도로 임계값 우회)** — 정규화 실패 시 같은 항목에 대한 재호출을 제한하거나, 단일 원문
   그대로만 검색하도록 지시.
5. **C (데이터 공백)** — 회덮밥/뼈매운탕/물냉면 canonical 메뉴 조사해서 추가.
6. **F (응답 속도)** — MCP 클라이언트가 서버 프로세스를 매 호출마다 새로 띄우지 않고 세션을
   재사용하도록 연결 방식 점검, 이동시간 계산도 정규화처럼 식당 목록을 한 번에 받는 배치
   도구로 전환. 정확성 문제는 아니라 5개 중 가장 낮은 우선순위.
